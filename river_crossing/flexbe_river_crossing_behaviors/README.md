# flexbe_river_crossing_behaviors

FlexBE behavior state machines for the river-crossing synthesis demonstration.
Four behaviors are included:

| Behavior | File | Description |
|---|---|---|
| `wgcf_demo` | `wgcf_demo_sm.py` | Hand-crafted seven-step solution to the classic WGCF puzzle; useful for validating the FlexBE setup before running synthesis |
| `synthesis_demo` | `synthesis_demo_sm.py` | Starter behavior with an empty container that can be populated by synthesis from the FlexBE WebUI |
| `Synthesis_Output` | `synthesis_output_sm.py` | Example state machine generated by the WGCF full-spec synthesis pipeline; illustrates the synthesized output structure with retry loops |
| `two_rivers_parsed` | `two_rivers_parsed_sm.py` | Example state machine generated by the two-rivers parsed-capability pipeline; uses `MoveState2R` and integer-valued destination parameters |

## Loading a behavior in FlexBE

The behaviors are installed as a `flexbe_behaviors` package.  In the FlexBE WebUI,
load them from the **Behavior** panel by selecting the behavior name.

For the hand-crafted `wgcf_demo`, set autonomy to `High` so transitions fire automatically.

For synthesized behaviors, re-add the `left`, `right` (and `middle` for two-rivers) input/output
keys to the container after loading, as synthesis resets them.  Set state-machine userdata:

```
left  = ['wolf', 'goat', 'corn', 'farmer']
right = []
middle = []   # two-rivers only
```

See the [river-crossing README](../README.md) for full execution instructions.
